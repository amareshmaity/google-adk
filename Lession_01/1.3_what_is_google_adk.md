# What is Google ADK 

The Agent Development Kit (ADK) is an open-source framework from Google for building, evaluating, and deploying AI agents and multi-agent systems. It’s a “code-first” toolkit: developers define an agent’s instructions, tools, and orchestration in ordinary source code rather than through a visual builder or a long prompt. 

<br/>

### How Google ADK came into existence? 

#### 1. Origins: an internal Google framework 
* Not built from scratch for the public 
* Already used inside Google to power:  
    * Agentspace 
    * Customer Engagement Suite (CES) 

* Later open-sourced so outside developers could build agents the same way 


#### 2. Public launch: Google Cloud Next 2025 

* Announced on April 9, 2025 
* Python only at first 
* Pitch: build an AI agent in under 100 lines of Python code 
* Later added support for other languages as well 

 

#### 3. Part of a bigger agent strategy, launched with two companions 

* Agent2Agent (A2A) protocol  
    * Open standard, announced the same day as ADK 
    * More than 50 launch partners 
    * Lets agents from different vendors and frameworks discover each other and collaborate 

 
* Agent Engine  

    * Fully managed runtime in Vertex AI for deploying agents to production 
    * Framework-agnostic: deploys agents built with ADK, LangGraph, CrewAI, or others 

 

#### 4. Competitive context 

* Microsoft already had AutoGen 
* OpenAI and others were shipping their own agent toolkits 
* ADK was Google’s answer for developers on the Gemini and Google Cloud stack 

 <br/>

## Key features of Google ADK 

#### 1. Built for multi-agent systems: 
Compose specialized agents into teams, each with a clear role such as planning, execution, review, or routing. 

#### 2. Works with any model: 
Optimized for Gemini, but runs models from other providers through adapters such as LiteLLM, so you aren’t locked into one vendor. 

#### 3. Supports multiple languages: 
Official SDKs for Python, Java, Go, and TypeScript make ADK a strong option for teams outside the Python ecosystem. 

#### 4. Native A2A support: 
Through the Agent2Agent (A2A) protocol, ADK agents can work with agents built on other frameworks or by other vendors. 

For example, an ADK agent can hand a task to a LangGraph or CrewAI agent without any custom integration code, because A2A gives them a shared language. 

 
#### 5. Strong Developer Experience: 
The adk web interface shows each prompt, tool call, and agent handoff, so you can see exactly what an agent did and why. 

#### 6. Built-in evaluation: 
Test agents against predefined scenarios and catch regressions whenever prompts, tools, or models change. 

#### 7. Structured context: 
Sessions, memory, tool outputs, and artifacts are stored as structured context instead of one long chat history, which keeps agents efficient on long-running tasks 

<br/>

## Trade-offs 

1. **Opinionated structure:** ADK enforces a set project layout and lifecycle. That’s fast when your project fits, and restrictive when it doesn’t. 

2. **Google Cloud gravity:** The framework is portable, but the smoothest deployment and operations run through Google’s ecosystem. Teams on other clouds get less of the benefit.
